Why Wiggle

Six design decisions.
One dependable engine.

From a single JVM to a fleet of cells, Wiggle treats isolation as a first-class deployment primitive — not an afterthought.

01 · Cellular

Cellular by design

A namespace is a cell: its own database, its own cluster. Grow by adding cells — resharding never migrates data. Each cell is an independent blast radius.

A Raft coordinator places instances by consistent hashing over epochs. The instance id carries its own routing — orders.e0.s3.01J… — so any party can compute the owning cell from the id alone.

02 · Durable

Durable execution

Workflow state is DB-backed rows, not a call stack. Crash mid-step → resume from durable state.

Exactly-once dispatch, at-least-once execution, lease-based recovery when a worker dies mid-step.

03 · State machine

State machine, not glue

A compiled graph, versioned by content hash. The workflow is data, not replayed code.

No determinism contract. step · gate · fork · choose · timers · signals — handlers can use clocks, randomness, any library.

04 · Pull-based

Pull & polyglot

Workers long-poll over gRPC. Java, Go, Python on the same server.

No inbound connectivity. No broker. Backpressure built in. Dispatch is by activity name — not language.

05 · Embeddable

Lightweight

One JAR + a database. Embedded in your JVM for tests.

PostgreSQL, MySQL, Oracle, SQL Server — or in-memory. No Elasticsearch, no sidecar mesh, no mandatory Kubernetes.

06 · Operable

Operable from day one

Web ops console, CLI, health probes, queue-lag monitoring.

Live trace of every instance over the workflow diagram. Cancel, signal, schedule, search by id or correlation id.

Architecture

Topology and placement are separate.

Clients and pull-based workers speak gRPC to cells. Each cell is a complete cluster with its own database. An optional Raft coordinator manages shard placement through epochs — without migrating in-flight data.

Placement

Consistent hashing + epochs

The coordinator publishes a shard → cell ring per epoch. The cell that owns an instance is determined entirely from the instance id — no global lookup, no routing table.

No data migration

Ring changes don't move data

When a new epoch starts, in-flight workflows stay in their current cell and finish there. New workflows follow the new ring. Existing data is never migrated.

Self-routing ids

An id knows its cell

The instance id carries epoch and shard — orders.e0.s3.01J…. Any party can compute the owning cell from the id alone.

Build workflows in code

Topology and logic stay separate.

Handlers are plain methods matched by name. No YAML, no replay, no determinism rules to memorise. The workflow is a graph — the code is just the set of steps.

// A complete, durable, parallel workflow — a compiled graph the server owns.
Blueprint orders = Workflow.define("order-fulfilment")
        .step("validate")
        .gate("in-stock")
        .fork(Branch.of("payment",  s -> s.step("authorise").step("capture")),
              Branch.of("shipping", s -> s.step("reserve-stock").step("print-label")))
        .combine("merge")
        .step("notify")
        .build();
// A Go worker implements steps by name — it interoperates with Java & Python.
worker := wiggle.NewWorker(client, "worker-1").
    Handle("order", "validate", func(o wiggle.Context) (wiggle.Context, error) {
        o["status"] = "VALIDATED"
        return o, nil
    }).
    HandleGate("order", "in-stock", func(o wiggle.Context) (bool, error) {
        return o["quantity"].(float64) > 0, nil
    }).
    Handle("order", "charge", func(o wiggle.Context) (wiggle.Context, error) {
        o["paymentRef"] = fmt.Sprintf("auth-%v", o["orderId"])
        return o, nil
    }).
    HandleEffect("order", "notify", func(o wiggle.Context) error {
        fmt.Println("shipped", o["orderId"]); return nil
    })
worker.Start(ctx)
from wiggle import Handlers, Worker

class OrderHandlers(Handlers):
    workflow = "order-fulfilment"          # methods ARE the steps

    def validate(self, o) -> dict:      # task → returns the new context
        return {**o, "status": "VALIDATED"}

    def inStock(self, o) -> bool:       # bool → a gate
        return o["qty"] > 0

    def notify(self, o) -> None:        # None → a side effect
        print("shipped", o["orderId"])

worker = Worker(client, "orders").register_handlers(OrderHandlers())
worker.start()
